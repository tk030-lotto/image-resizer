# 画像をまとめてリサイズする単機能ツール「Image Resizer」を作った

▼ ブラウザですぐにお使いいただけます（完全無料・サーバー送信なし）
https://tk030-lotto.github.io/image-resizer/

画像をWebサイトに掲載したり、SNSへ投稿したり、メールや資料に添付したりするとき、画像サイズが大きすぎることがあります。

1枚だけなら、それほど問題ではありません。

しかし、複数の画像を同じようなサイズに揃えようとすると、画像を選択して、サイズを変更して、保存して……という作業を繰り返すことになります。

そこで今回は、画像の**「長辺」を指定するだけで、複数の画像をまとめてリサイズできる単機能ツール「Image Resizer」**を作りました。

## Image Resizerとは

Image Resizerは、ブラウザ上で動作する画像一括リサイズツールです。

基本的な操作は非常にシンプルです。

1. 画像を追加する
2. 長辺のサイズを指定する
3. 変換を開始する

これだけです。

複数の画像をまとめて処理し、縦横比を維持したままリサイズします。

例えば、4000×3000pxの画像に対して長辺を1280pxと指定すると、

```text
4000 × 3000
      ↓
1280 × 960
```

となります。

縦長の画像であれば、

```text
3000 × 4000
      ↓
960 × 1280
```

となります。

正方形なら、

```text
4000 × 4000
      ↓
1280 × 1280
```

です。

つまり、ユーザーが細かい計算をする必要はありません。

## 小さい画像は拡大しない

このツールでは、指定したサイズよりも元画像のほうが小さい場合、画像を拡大しません。

例えば、

```text
元画像
800 × 600

指定
1280px

結果
800 × 600
```

となります。

小さな画像を無理に拡大すると画質が劣化するためです。

「長辺を1280pxにする」という指定でも、1280pxより小さい画像まで拡大する必要はないと考え、この動作にしています。

## 元画像は変更しない

画像を一括処理するツールでは、元画像を誤って上書きしてしまわないことも重要です。

Image Resizerでは、元画像を直接変更しません。

リサイズした画像は別の出力先へ保存します。

デフォルトでは、

```text
選択フォルダ/
└── resized/
    ├── image01.jpg
    ├── image02.jpg
    └── image03.jpg
```

という構成になります。

元画像を残したまま、リサイズ後の画像だけを別に管理できます。

## 同名ファイルも上書きしない

もう一つ、ファイル処理では「同じ名前のファイルがすでに存在していたらどうするか」という問題があります。

Image Resizerでは、既存ファイルを無条件に上書きしないようにしています。

例えば、

```text
image.jpg
```

がすでに存在している場合、

```text
image_001.jpg
image_002.jpg
```

のように連番を付けて保存します。

開発途中のコードレビューでもこの部分を確認し、出力先に存在するファイル名を事前に取得して衝突を防ぐ処理を追加しました。

単純な画像リサイズですが、実際に使えるツールにするには、こうした細かい部分も重要になります。

## ブラウザだけで処理する

Image Resizerの大きな特徴の一つが、**画像を外部サーバーへ送信しない**ことです。

画像処理はブラウザ内で完結します。

```text
画像
 ↓
ブラウザ
 ↓
Canvasでリサイズ
 ↓
ローカルへ保存
```

画像をアップロードしてサーバー側で処理する方式ではありません。

そのため、画像を外部へ送信したくない場合でも利用できます。

また、完成したビルドはJavaScriptやCSSを内包した単一HTMLファイルになっており、オフラインでも利用できる構成にしています。

## ブラウザによる保存方法の違い

ファイルの保存については、ブラウザによって対応状況が異なります。

ChromeやEdgeなど、File System Access APIに対応したブラウザでは、保存先フォルダを選択して直接ファイルを書き込めます。

一方、対応していないブラウザでは、リサイズした画像をZIPファイルとしてまとめてダウンロードします。

つまり、

```text
Chrome / Edge
    ↓
指定フォルダへ直接保存

その他のブラウザ
    ↓
resized.zip
```

という構成です。

ブラウザの違いによって使えなくなるのではなく、それぞれに合わせた保存方法を用意しました。

## 対応する画像形式

現在の対応形式は、

* JPG
* JPEG
* PNG
* WebP

です。

基本的には入力形式を維持して出力します。

また、WebPについては実行環境での対応状況を確認し、必要に応じてPNGへフォールバックする仕組みも入れています。

## あえて画像編集機能は入れない

Image Resizerは、画像編集ソフトを目指しているわけではありません。

そのため、初期バージョンでは、

* トリミング
* 回転
* フィルター
* 明るさ調整
* AI画像処理
* 顔認識
* クラウドアップロード
* 画像管理

などは対象外としています。

目的はあくまで、

**「複数の画像を、指定した長辺サイズにまとめてリサイズする」**

ことです。

機能を増やせば便利になるとは限りません。

単機能ツールとして、必要な処理だけを確実に行うことを優先しています。

## 開発構成

開発には、

* TypeScript
* Vite
* Vitest
* Canvas API
* File System Access API

などを使用しています。

ソースコードは機能ごとに分離しています。

```text
src/
├── main.ts
├── style.css
├── core/
│   ├── resize.ts
│   ├── filename.ts
│   └── format.ts
├── io/
│   ├── drop.ts
│   └── writer.ts
└── ui/
    └── result.ts
```

リサイズ計算、ファイル名処理、画像形式判定、ファイル保存などを分けています。

単純なツールでも、後から修正しやすい構成にしておくことは重要です。

## テストも実施

完成したから終わり、ではなく、主要な処理について単体テストを実施しました。

結果は、

```text
Test Files  5 passed (5)
Tests       25 passed (25)
Duration    ~1.8s
```

となりました。

テスト対象には、

* 画像サイズ計算
* 拡大防止
* ファイル名の連番処理
* 大文字・小文字を考慮したファイル名判定
* 画像形式判定
* フォルダ名のサニタイズ
* 既存ファイル名の取得
* ドラッグ＆ドロップによるファイル抽出

などを含めています。

単機能だからテストが必要ない、ということではありません。

むしろ機能が少ないからこそ、主要な処理が正しく動いているか確認しやすいというメリットがあります。

## 最終的なビルド

本番用のビルドでは、TypeScriptの型チェックとViteによるビルドを実行しました。

生成されたファイルは、

```text
dist/index.html
44.91 kB
```

です。

JavaScriptとCSSを単一HTMLに内包しているため、完成後は非常にシンプルな形で配布できます。

## まとめ

今回作ったImage Resizerは、かなり単純なツールです。

できることは、

**「複数の画像を、指定した長辺サイズにまとめてリサイズする」**

これが基本です。

ただし、その中に、

* 縦横比の維持
* 小さい画像の拡大防止
* 元画像の保護
* 同名ファイルの上書き防止
* 複数画像の一括処理
* オフライン処理
* ブラウザごとの保存方式
* エラー処理
* 単体テスト

といった、実際に使うための機能を組み込んでいます。

「何でもできる画像編集ソフト」ではなく、**一つの作業に絞った小さなツール**です。

こうした単機能ツールは、機能を増やしていくよりも、最初に「何をしないか」を決めることが重要なのかもしれません。

Image Resizerも、画像編集ソフトへ広げるのではなく、まずは「画像の一括リサイズ」という一つの機能を、シンプルかつ安全に使えるところまで仕上げました。
